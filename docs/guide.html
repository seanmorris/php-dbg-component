Quickstart and API

A JavaScript component for running and debugging PHP in the browser with php-dbg-wasm. Supports PHP 8.0–8.5, breakpoints, variable editing, and execution from JavaScript. PHP runs in a worker by default.

Run locally

Clone the repository, install its dependencies, and start the example server:

git clone https://github.com/seanmorris/php-dbg-component.git
cd php-dbg-component
npm ci
npm run start

Open http://localhost:9120/. Click Run to stop at line 3, then Continue to print Result: 5.

The server uses a compatible installed php-dbg-wasm package if one is available. Otherwise it downloads the preview build recorded in runtime-lock.json and verifies its checksum. That file pins a GitHub build artifact and its source commit.

Build this documentation site locally 
npm run setup:runtime
RUNTIME_BUNDLE=./runtime-bundle npm run build:docs
npm run start

Open http://localhost:9120/docs/. If the server is already running, keep it running after the build.

Embed the component

For an existing project, install the component from GitHub:

npm install github:seanmorris/php-dbg-component

Serve the component modules and a matching runtime directory over HTTPS or localhost. To use the preview runtime, run npm run setup:runtime in the cloned repository and copy runtime-bundle/runtime/ to your site's runtime/ directory. Keep its files together. See runtime hosting for extensions and native builds.

This example assumes the page can serve node_modules/ and runtime/ at the paths shown:

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>PHP debugger</title>
<link rel="stylesheet" href="./node_modules/php-dbg-component/src/styles.css">
<div id="debugger"></div>
<script type="module">
  import {PhpDebugger} from './node_modules/php-dbg-component/src/index.mjs';

  const dbg = new PhpDebugger({
    runtimeBaseUrl: './runtime/',
    version: '8.4',
    code: '<?php\n$n = 2;\n$n += 3;\necho $n;',
    breakpoints: [3]
  });
  dbg.mount(document.querySelector('#debugger'));
</script>
</html>

mount() creates the textarea and controls. Runtime downloads begin when the user clicks Run or your code calls run() or prepare(). Breakpoint lines start at 1.

With a bundler, import PhpDebugger from 'php-dbg-component' and the stylesheet from 'php-dbg-component/styles.css'. Preserve the module worker; use workerUrl if your build emits it at a different URL. Call await dbg.destroy() when removing the integration.

Live debugger

Click Run to pause on line 5 inside total(). Expand $item, edit its price, and use Step over to execute the assignment. Select a frame to inspect its variables. The unchanged example prints Cart total: 24.

Loading the interface. PHP downloads when you click Run.

Editor libraries load when selected. The selected PHP version loads on its first run. Components on this page share downloaded binaries and compiled modules.

Edit variables while paused

Using the dbg instance from the embedding example, start a run without awaiting its completion. Wait for the breakpoint, inspect the variable, then assign a PHP expression:

const done = dbg.run();
await dbg.whenPaused();

const locals = await dbg.inspect('variables');
const n = locals.find(value => value.name === 'n');
await dbg.setVariable(n.reference, '40');

await dbg.setBreakpoints([]);
await dbg.continue();
const result = await done;
console.log(result.stdout); // "43"

Use children(reference) to expand arrays or objects and edit their writable children. evaluate(expression) also accepts assignments. selectFrame(index) changes the frame used for inspection and evaluation; frame 0 is the innermost call.

Variable references expire when execution resumes or ends. Inspect again after stepping. PHP enforces visibility, types, and readonly properties; failed edits report the PHP error.

Run PHP tests from JavaScript

A controller can execute PHP without mounting a view. Test mode skips breakpoints and returns output, exit status, diagnostics, and assertion results:

const test = new PhpDebugger({
  runtimeBaseUrl: './runtime/',
  code: '<?php echo 6 * 7, "\\n";'
});

try {
  const result = await test.run({
    mode: 'test',
    expect: {stdout: '42\n', stderr: '', exitCode: 0},
    timeoutMs: 5000
  });
  console.log(result.test.status); // "passed"
} finally {
  await test.destroy();
}
Not run

run() resolves to {runId, version, status, exitCode, stdout, stderr, diagnostics, durationMs, test}. PHP failures resolve as data; invalid API arguments and overlapping runs throw. test.status is passed, failed, or unchecked.

timeoutMs counts time running PHP, excluding loading and pauses. Pass an AbortSignal as signal to cancel a run. Your application can await runs sequentially or run separate controllers in parallel; each run has its own memory and virtual files.

Run a test when a custom element connects 
<php-debugger runtime-base-url="./runtime/" autorun mode="test">
  <textarea><?php echo "ok";</textarea>
  <script type="application/json" data-expect>
    {"stdout":"ok","exitCode":0}
  </script>
</php-debugger>
<script type="module">
  import {definePhpDebugger} from './node_modules/php-dbg-component/src/element.mjs';
  definePhpDebugger();
</script>

Registration and autorun are explicit. Listen for phpdbg-testresult on the element to receive the result in event.detail. Removing the element destroys its controller.

Sources and editor adapters

The controller reads its source once at the start of each run. Use code for a string or async getter, or source for an element or adapter.

SourceOption
Stringcode: '<?php echo 42;'
Variable or async loadercode: () => currentPhpCode
Textarea or inputsource: document.querySelector('textarea')
Other elementsource: document.querySelector('pre') reads textContent
Existing editorsource: adapter

Import only the adapter for your editor:

import {createAceAdapter} from 'php-dbg-component/adapters/ace';

const adapter = createAceAdapter(existingAceEditor);
const dbg = new PhpDebugger({runtimeBaseUrl: './runtime/', source: adapter});
dbg.mount(document.querySelector('#controls'));

// When removing the integration:
await dbg.destroy();
adapter.dispose();

CodeMirror adapters use createCodeMirror5Adapter from 'php-dbg-component/adapters/codemirror5' and createCodeMirror6Adapter from 'php-dbg-component/adapters/codemirror6'. CodeMirror 6 requires @codemirror/state and @codemirror/view.

Adapters add breakpoint gutters, current-line markers, and temporary read-only state. Your application owns the editor instance and its cleanup. The core component has no Ace or CodeMirror dependency.

PHP versions and extensions

const dbg = new PhpDebugger({
  runtimeBaseUrl: './runtime/',
  version: '8.4',
  extensions: ['curl'],
  code: '<?php echo extension_loaded("curl") ? "yes" : "no";'
});

await dbg.setVersion('8.5');
const result = await dbg.run({mode: 'test'});

The default version is 8.4. Supported versions are 8.0–8.5. setVersion() stops an active run and selects the version for the next run. Host the artifacts for every version you offer.

Extensions are explicit. The loader downloads the selected runtime, requested extensions, and their declared dependencies. Components share these downloads and compiled modules across the page.

Loading extensions

extensions: ['curl'] resolves to ../php-wasm-curl/VERSION.mjs relative to runtimeBaseUrl. Override that URL with extensionUrls: {curl: './vendor/curl/8.4.mjs'}, or supply an extension as {module: './vendor/custom/8.4.mjs'}. Keep the extension's dependencies beside its modules.

This check loads curl and calls extension_loaded('curl'). HTTP requests made through curl still follow browser CORS rules.

Not loaded

Worker and main-thread execution

execution: 'worker' is the default and allows hard termination. Use execution: 'main' when PHP needs page DOM access through vrzno. Main-thread pause and stop are cooperative; a blocking native call can block the page. dbg.capabilities.hardStop reports whether hard termination is available.

Execute trusted PHP. A same-origin worker can access network and browser APIs.

API reference

Execution methods return promises. Start a run with const done = dbg.run() when you need to interact with it before completion.

MethodBehavior
prepare()Download and initialize the selected runtime without executing the source.
run(options), restart(options)Run PHP and resolve its result. Restart first cancels an active run.
pause(), whenPaused()Request a pause or wait for a breakpoint, step, or exception stop.
continue()Resume until the next pause or completion.
stepInto(), stepOver(), stepOut(), until(), leave()Control execution with phpdbg stepping commands.
inspect(scope, {frame})Inspect variables, globals, constants, functions, classes, files, or frames.
children(reference, {offset, limit})Expand a value. Default page size: 100; maximum: 1000.
selectFrame(index)Select the frame for inspection and evaluation.
evaluate(expression, {frame})Evaluate a PHP expression in a paused frame.
setVariable(reference, expression)Assign a PHP expression to a writable variable or child value.
setBreakpoints([...])Replace breakpoints while idle or paused. Accepts line numbers or {file, line, enabled}.
setCode(code)Set a string or getter for the next run.
setVersion(version)Stop execution and select the next runtime version.
mount(element)Create the optional debugger view.
stop(), destroy()Cancel execution. Destroy also removes the view and component listeners.

Events and state

dbg.addEventListener('output', ({detail}) => {
  console.log(detail.channel, detail.text);
});
dbg.addEventListener('complete', ({detail}) => {
  console.log(detail.status, detail.exitCode);
});

Other events include statechange, pause, locationchange, framechange, variablechange, breakpointchange, versionchange, sourcechange, diagnostic, and testresult. Each is a CustomEvent with data in detail.

Read dbg.state, dbg.location, dbg.breakpoints, and dbg.result for current state. Output channels are stdout, stderr, and debug.

See the TypeScript declarations for option, event, and result types, and the README for virtual files, custom elements, and lifecycle details.

CSS and themes

The view uses light DOM and php-debugger- classes. Load the optional stylesheet and override its CSS variables, or supply your own rules:

.php-debugger {
  --php-debugger-bg: #131b27;
  --php-debugger-fg: #e7edf5;
  --php-debugger-accent: #8ce4cb;
  --php-debugger-border: #35465c;
  --php-debugger-radius: 4px;
}
.php-debugger-button { font-family: inherit; }

The root exposes data-state and data-test-status for state styling. Use the live debugger's theme selector to test page-level overrides.

Host runtime files

Serve matching bridge v1 artifacts from php-dbg-wasm. Copy the complete runtime directory, including wrapper modules, .mjs loaders, .wasm binaries, .assets.json manifests, and any .data files. The manifests identify binary filenames, checksums, and dependencies.

public/
  runtime/           # runtime-bundle/runtime/
  php-wasm-curl/     # runtime-bundle/php-wasm-curl/
  php-wasm-dom/      # runtime-bundle/php-wasm-dom/
  php-wasm-libxml/   # runtime-bundle/php-wasm-libxml/

Set runtimeBaseUrl: './runtime/' for a page at this root. Include the extension directories you request and their dependencies. Serve .mjs as JavaScript, .wasm as application/wasm, and manifests as JSON. HTTPS or localhost is required for checksum verification; file:// cannot load the module workers.

A 404 for php8.4-dbg-worker.mjs.assets.json means the runtime URL does not contain that build's manifest. Check the deployed directory and the requested version. The component rejects artifacts that lack bridge v1.

To use native builds from a local php-wasm checkout, start the example server with PHP_WASM_ROOT=/path/to/php-wasm npm run start. See the native build commands and documentation deployment instructions.
